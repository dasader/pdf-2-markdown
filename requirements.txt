# docling은 고정한다. 2.118은 레이아웃 모델에 torch.compile을 기본으로 켜는데
# (layout_options.engine_options.compile_model=True), 이 이미지에는 g++가 없어
# 컴파일이 페이지마다 실패·폴백한다 — 51p 문서가 5분 안에 끝나지 않는다. 핀 없이
# 재빌드하면 이 상태가 그대로 배포된다.
#
# g++를 넣으면 이야기가 달라진다. 컴파일은 프로세스당 한 번 내는 선불이라, 워커처럼
# 한 프로세스로 잡을 계속 처리하면 상환된다. 실측(공문서 11·18·29·45p + 11p 재실행을
# 한 프로세스에서 연속 처리):
#   첫 잡      36.8s → 127.6s   (선불 약 91초)
#   이후 4잡   128.3s → 108.0s  (-16%, 문서별로 8~24% 단축)
#   peak RSS   4.01GB → 3.83GB
# 손익분기는 약 18잡. 같은 문서를 다시 돌린 마지막 잡도 빨라져(16.2s → 13.6s) 페이지
# 크기가 바뀌어도 재컴파일이 걸리지는 않았다. 다만 워커가 OOM으로 죽으면 재시작할
# 때마다 선불을 다시 낸다 — 무거운 문서가 잦으면 상환되지 않는다.
#
# 그 외 2.112~2.118에 PDF 경로 개선은 없다 — 출력이 2.111과 바이트 단위로 같았다.
# 올리려면 (1) 이미지에 g++ 추가 (2) compile_model 명시 (3) 워커 재시작 빈도 확인.
docling==2.111.0
